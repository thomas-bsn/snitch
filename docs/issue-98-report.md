# File de tâches par clip — #98

Direction E validée par l’utilisateur, prototype conservé dans le commit 93bb11a de la branche prototype/issue-98-task-queue. Les fichiers de prototype et le contournement de session de développement sont retirés de l’implémentation.

La file présente les traitements par étape, avec les cartes d’un clip visibles dans chacune des étapes concernées. Une tâche annulée reste visible et ne compte pas comme une réussite. « Terminé » signifie que tous les traitements planifiés ont réussi, pas que toutes les fonctions de Snitch ont été exécutées. Trois clips terminés sont conservés dans l’historique de la file. L’historique page dix clips côté serveur, et les travaux actifs vingt clips. Les titres originaux viennent de l’API des clips ; le jeu est extrait uniquement des noms au format jeu/date/heure reconnu.

La planification propose la transcription (étape 0) et l’analyse vocale (étape 1) selon les capacités déclarées par les workers non révoqués. Le serveur résout la piste et la version. Un worker compatible acquiert la tâche ; aucun choix arbitraire de machine n’est demandé. La transcription conserve la confirmation de remplacement des corrections. L’analyse vocale exige une transcription ; le serveur applique cette condition et la configuration des modèles. Les autres étapes dérivées sont gérées par leurs pipelines existants. Priorité et tentatives utilisent les valeurs par défaut du serveur.

La file affiche le worker, le GPU, sa mémoire et le nombre de traitements actifs dans la même carte que les réglages de concurrence. Les filtres précèdent les colonnes de progression. Celles-ci gardent une hauteur uniforme sur grand écran ; les cartes d’alerte sont jaunes et le statut affiché est en langage utilisateur (« En cours », « En attente », « Terminé »). La pagination utilise deux flèches avec le numéro de page au centre. La planification utilise des cartes de choix numérotées à partir de l’étape 0. Le prototype autonome est disponible dans [docs/prototypes/issue-98-queue.html](prototypes/issue-98-queue.html).

Vérifications : compilation web réussie après les derniers changements ; tests Go jobs/workers/httpapi et PostgreSQL TestFoundation/job_queue avec Testcontainers/Colima validés précédemment ; Chromium avec API synthétique, états de file et de planification, pagination et captures à 2048 px sans erreur JavaScript. Les vérifications navigateur ne lancent ni transcription réelle ni parcours OAuth.
